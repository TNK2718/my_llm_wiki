starter 関係: employment / manufacturing / org_hierarchy / product_variant / governance / compliance

starter 型・関係の意味:
- person          自然人 (実在の個人)。attributes: birth_date (YYYY-MM-DD) / nationality
- organization    会社・チーム・組織・大学・政府 (**固有名詞の組織名のみ**)。attributes: org_type ∈ {company,lab,team,university,government,nonprofit,other} / founded_year / headquarters
- product         商品・サービス (**固有名詞の製品名のみ**)。attributes: release_date (YYYY-MM-DD) / category
- project         プロジェクト・施策・計画。attributes: started_at / ended_at
- contract        サービス記述書・利用規約・SLA・セキュリティ補遺・DPA 等の**法的/契約文書**。attributes: contract_type ∈ {service_description,terms_of_service,sla,security_addendum,data_processing,other} / effective_date / valid_until / jurisdiction / url / version / sla_uptime_percent (数値、99.9 等) / sla_response_time_minutes / rto_hours / rpo_hours
- employment      from=person, to=organization。attributes: role, start_date, end_date
- manufacturing   from=product, to=organization (**製造元・提供元・発売元の組織**)。属性なし
- org_hierarchy   from=parent_org, to=child_org (親子組織)。属性なし
- product_variant from=parent_product, to=variant_product (**製品ファミリのバリアント**)。属性なし
- governance      from=product, to=contract (**製品がどの契約に従うか**)。属性なし
- compliance      from=contract, to=**standard 名 (テキスト**, "ISO 27001" 等)。attributes: certified_until (YYYY-MM-DD or null)

**entity 化禁止語** (カテゴリ/ロール/抽象): "SaaS 製品" "AI SDLC ツール" "クラウド・サービス" "ソフトウェア" "許可ユーザー" "管理者" "オファリング" "プラン" 等。

**関係抽出のコツ:**
- 製品名が組織名で始まる (例 "IBM Bob") → 明示なしでも manufacturing(product, org) を出す
- 製品ファミリ (Pro/Plus/Ultra/Enterprise/Trial) → 各バリアントごとに manufacturing + product_variant(親, 子) の 2 行
- contract と product を governance で繋ぐ。compliance の to は standard 名 (テキスト)、entity ではない
- product↔product のバリアント以外は weak_relations、org_hierarchy は org↔org のみ

ルール:
- **starter 型・関係に当てはまる主張は entities / relations に出す**。
- starter に当てはまらない型（algorithm, standard, document など）の主張は entities に **`new_table_proposal` を埋めて** 出す:
  {"proposed_type": "algorithm", "canonical_name": "FFT", ..., "new_table_proposal": {"table": "algorithm", "columns": [{"name":"category","type":"TEXT"}], "rationale":"資料中の頻出"}}
- starter junction に当てはまらない関係（mentions, similar_to, part_of など）は weak_relations に積む。
- 主張に確信が持てなければ confidence を 0.3 未満に。低 conf 主張は別途 staging に積まれる。
- 数値・日付・固有名詞は原文どおり正確に。
- attributes の値は **必ず資料に明記された情報**。推測しない。
- 同じ entity を複数 chunk から検出した場合は同じ canonical_name を使う。
- confidence: 1.0 は使わない（人手 verdict 専用）。LLM 抽出は 0.0〜0.95 の範囲で。
- 既存テーブルに紛らわしいエンティティがありそうなら `existing_matches` に候補を任意で書いてよい (例: `[{"table":"organization","name":"Acme Corp","rationale":"略称が一致"}]`)。**類似度スコアは出さないこと**（pipeline 側で決定論的に算出する）。確信がないときは空配列で構わない。
